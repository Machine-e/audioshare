# 独立传输音量：当前证据与未完成项

用户要求调整传输音量而非系统音量，并希望增益超过原有上限。仅移除旧滑块、
控制测试音或把百分比改为 200% 均不算完成这项需求。

## 已确认事实（2026-10-11）

- 当前 Android 使用系统 A2DP 发送其他应用的媒体；AudioShare 没有这些音频样本。
- Windows `AudioPlaybackConnection` 只管理连接，音频由操作系统播放。
  官方接口未暴露 PCM 读取、播放节点或增益设置。
- 在当前 Windows 机器上只读枚举 WASAPI 音频会话：目标手机的 A2DP SNK
  播放会话归属于 `Audiosrv`，并非 AudioShare。未修改会话或终端音量。
- 枚举到的普通录音端点没有提供可直接替代当前播放路径的目标手机 PCM 端点。
  这是当前机器上的观察，不是所有驱动的通用结论。
- 旧 Android `setStreamVolume` 调用及其权限已移除。旧 channel 的写入方法返回
  `independent_volume_unavailable`，不会把传输增益请求转发到系统媒体音量。

## 需要选择的音频通路

### Windows 接收会话声道音量试验（2026-10-12）

用户明确要求只调整接收后的声音，授权实际尝试。当前机器存在唯一处于 Active 的
A2DP SNK 会话，属于 Windows 音频服务；该会话支持 `IChannelAudioVolume`。
试验只调用声道音量接口，将两个声道由 `1.0` 降到 `0.25`，持续 8 秒后恢复。
期间 `ISimpleAudioVolume` 读数保持 `1.0`，输出设备主音量保持 `0.2`；
恢复返回 S_OK，再次只读查询确认两个声道均为 `1.0`。

这证明当前机器允许独立设置接收会话的声道衰减，不证明手机绝对音量没有联动，
也不证明实际听感变化：Android 未通过 ADB 连接，仍待用户听音和手机音量观察。
现已加入 Windows“接收音量 · 试用”滑块（0–100%）。正式代码要求所选设备名在
APC 设备列表中唯一，且只匹配 Audiosrv 进程中唯一活动、名称以所选手机的
`(手机名称 A2DP SNK)` 结尾的会话；读取/刷新时枚举定位，拖动期间复用同一会话实例，
每次写入检查会话仍活动且连接代次有效，拒绝过期连接。失效后需手动刷新重新定位。
这是当前驱动的保守名称匹配，不是跨驱动的稳定设备标识，不匹配时禁用滑块。
100% 为首次读取的原始声道值；停止、断开和正常退出会恢复原值，若检测到外部
调整则不覆盖。输出设备切换后需刷新；异常终止可能遗留系统持久化的声道衰减。
本次临时探针仅在
唯一活动 A2DP SNK 会话时执行。正式匹配代码已在当前活动会话只读定位并以
100% 原值写回通过。2026-10-13 用户反馈滑块有效，但未单独确认手机音量是否联动。
拖动现以 50ms 合并请求，保持至多一次在途写入、优先最新值，松手立即提交最终值；
后台旧返回不覆盖拖动位置，断开/销毁取消待发请求。

2026-10-13 验证：74 项 Flutter 测试、静态分析及 Windows Release 构建通过；
覆盖慢写入合并、拖动值不被旧响应覆盖、松手提交、断开取消、重连恢复。
当前机器对同一会话进行 100 次原值校验/写入，平均约 0.22ms（不含 Flutter 通道延迟）。
实际桌面检查亮/暗主题标题栏与细边框颜色贴近背景；原生缩放和窗口按钮保留。

官方接口文档：<https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nn-audioclient-ichannelaudiovolume>。
声道音量范围仍为 0–1；该试验不支持超过原始音量的增益。

此前已向用户询问是否允许新增音频捕获和局域网传输，或必须保持纯蓝牙。
回复前不引入网络音频或新的捕获权限。

1. 若允许捕获和局域网：使用 Android AudioPlaybackCapture、用户授权的
   MediaProjection 会话与前台服务，建立应用自己的音频传输和 Windows 播放流。
   需要处理捕获撤销、后台生命周期、鉴权、抖动缓冲和断线恢复。受保护或禁止捕获的
   播放源不保证可用，不能宣称替代全部系统音频。
2. 若保持纯蓝牙：需进一步验证可访问的 A2DP PCM 接收路径，或由 Android 捕获后
   经独立蓝牙通道传音频。后者仍需要捕获授权，还要验证编码、吞吐和延迟；
   Windows 的普通单会话音量仅有 0–100% 衰减，不能替代超过 100% 的增益处理。

无论采用何种方案，增益应作用于应用拥有的 PCM 流，并包含平滑变更、削波处理、
静音及 100% 原始电平。验收需验证系统音量保持不变、静音有效、超过 100% 能实际
提高低电平信号，以及取消连接后音频停止。必须用双端实际播放验证。
